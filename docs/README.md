## Architecture

This project is built as a **full-stack, event-driven system** with a clear separation between the React frontend, a modular NestJS backend, a relational data layer (PostgreSQL via Prisma), and a Kafka-based streaming layer. At a high level, the frontend talks to the backend over REST; the backend persists state in Postgres, publishes and consumes events via Kafka, and delegates AI explanations to an external LLM provider. The high-level component diagram and data-flow sequences are documented in `docs/architecture/` (see `system-architecture.mmd` and `dataflow.mmd`).

On the backend, the NestJS app is organised into feature modules: `Documents`, `Transactions`, `Anomalies`, `AiAssistant`, and `Streaming`, all sharing a common `PrismaModule` for database access. Traditional CRUD and query operations (uploading documents, listing transactions, fetching anomalies) go through controllers and services into PostgreSQL. Streaming concerns are isolated in the `Streaming` module, which owns the Kafka producers and consumers: a document-parser consumer that turns uploaded PDFs into structured transactions, a stream-enricher that computes rolling features for live transactions, and a fraud engine that writes `anomaly_events` and `document_risk_summary` records back to the database.

The frontend is a React + Vite single-page app with a small router and a feature-first structure. It provides three main views: a **Documents** page (list + upload), a **Document Detail** page (parsed transactions, anomaly flags, and an AI explanation panel), and a **Live Alerts** page for streaming fraud events. A lightweight API client layer (`src/api/*`) encapsulates all HTTP calls to the NestJS backend. 

The underlying data model is captured in an ER diagram (`docs/architecture/database-erd.mmd`): users own documents; documents contain transactions and have a risk summary; both document-based and live-stream transactions can generate anomaly events; and optional AI conversation tables capture chat history when the assistant explains why a document or transaction looks suspicious.
